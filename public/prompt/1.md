# ChatGPT-Style Long-Term Memory Architecture for an AI Assistant

## Objective

Design an AI assistant that maintains persistent user memory across conversations while ensuring efficient retrieval, scalable context management, and intelligent memory updates. The system should avoid loading all stored memories into every prompt and instead retrieve only the memories relevant to the current user query.

# Workflow

## Step 1 – Receive Request

The API receives:

* userId
* chatId
* messages
* selected model
* agent configuration

The latest user message is identified as the primary retrieval query.

---

## Step 2 – Retrieve Conversation Context

Retrieve:

* Recent messages (last 6–10)
* Existing chat summary
* Agent configuration
* System prompt

The recent conversation preserves immediate context while the summary compresses older parts of the conversation.

---

## Step 3 – Memory Retrieval

Do NOT load every stored memory.

Instead:

Search the memory database using semantic similarity.

Example:

User:

"I need travel recommendations."

Relevant memories:

✓ User prefers budget travel

✓ User dislikes flying

✓ User lives in India

Ignore memories such as:

✗ Favorite programming language

✗ Preferred IDE

Only inject memories related to the current request.

---

## Step 4 – Prompt Construction

Construct the final prompt using:

System Prompt

↓

Agent Instructions

↓

Relevant User Memories

↓

Conversation Summary

↓

Recent Messages

↓

Current User Message

The model never receives the entire database.

Only compressed and relevant context.

---

## Step 5 – Model Reasoning

Invoke the LLM.

The model may:

* answer directly
* call tools
* request additional information

---

## Step 6 – Tool Execution

If the model requests tools:

Execute them.

Examples:

* Calculator
* Search
* Weather
* Database statistics
* Knowledge base retrieval
* Calendar
* Email
* Memory tools

Tool outputs are appended to the conversation and sent back to the model.

Repeat until the model produces a final response.

---

## Step 7 – Stream Response

Return tokens immediately to the frontend.

The user should see streaming text instead of waiting for the complete response.

This minimizes perceived latency.

---

## Step 8 – Memory Extraction

After the response finishes, run a second lightweight memory extraction step.

Prompt example:

"Should anything from this conversation become long-term memory?

Return:

* SAVE
* UPDATE
* DELETE
* IGNORE

Include the structured memory."

---

## Step 9 – Memory Decision

The extractor determines whether the conversation contains information worth remembering.

Do NOT save:

* greetings
* temporary requests
* one-time questions
* calculations
* jokes
* random chat

Save:

* preferences
* personal profile
* recurring habits
* long-term goals
* favorite technologies
* permanent settings
* communication style

---

## Step 10 – Update Memory Store

If SAVE:

Insert a new memory.

If UPDATE:

Replace the previous value.

Example:

Old:

Preferred language = Python

New:

Preferred language = Rust

Update the existing record instead of creating duplicates.

If DELETE:

Remove obsolete memories.

If IGNORE:

No database changes.

# Retrieval Strategy

Instead of:

SELECT *

FROM user_memories

WHERE user_id = ?

Use:

Current User Message

↓

Embedding

↓

Vector Search

↓

Top 5 Relevant Memories

↓

Prompt

This keeps prompts small and improves relevance.

# Performance Optimizations

• Cache recent chat messages using TanStack Query.

• Store conversation summaries after every 5–10 messages.

• Retrieve only the most relevant memories through vector search.

• Stream model responses to reduce perceived latency.

• Run memory extraction asynchronously after the response.

• Execute title generation and conversation summarization in background jobs.

• Update memories without blocking the user response.
